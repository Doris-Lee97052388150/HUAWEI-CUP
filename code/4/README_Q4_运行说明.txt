问题四第一版求解器与测试输出
============================

1. 核心程序
   q4_solver.py

2. 推荐放置位置
   HUAWEI-CUP/code/4/q4_solver.py

3. 推荐运行命令
   python q4_solver.py --root "D:/.../HUAWEI-CUP"

   若只想显式指定问题三输出与结果模板：
   python q4_solver.py --q3-zip ".../output.zip" --template ".../结果提交模板.xlsx"

4. 默认行为
   - 固定问题三最终运输与中继调度结果；
   - 自动构造运输不可拆分单元；
   - 基于实际“运输架次—中继架次”关联构造中继超图；
   - 报告严格继承口径下的结构性不可分；
   - 在“中继任务按组完整复制”的扩展口径下完整枚举 K=2、K=3；
   - 采用时间区间最大重叠精确核算组内最少资源；
   - 输出全部候选、Pareto候选、理论中继下界方案、主提交方案；
   - 自动重新编号组内实体资源并审计时间冲突；
   - 自动回填 Q4_分区配置；
   - 尽可能多地生成诊断图、论文备选图；默认每图同时输出 PNG 和 PDF；
   - 自动生成 Q4_图表说明.tex、Q4_参考文献.tex、Q4_结果宏.tex。

5. 当前沙箱实跑说明
   当前会话直接挂载了 output.zip、结果提交模板.xlsx 与 body.tex；原始节点坐标表和 DEM 未挂载到当前运行目录，
   因此本次测试实际生成 52 幅不同图表（52 PNG + 52 PDF），不含真实 DEM 背景的地理分区图。
   将脚本放回完整 HUAWEI-CUP 工程目录后，程序会自动尝试发现节点坐标和 DEM，并进一步生成地理分区类图表。

6. 当前主提交方案
   K=2：运输侧零增配，中继无人机总需求4架，中继能源组件总需求6组；相对库存缺2架中继无人机。
   K=3：运输侧零增配，中继无人机总需求6架，中继能源组件总需求8组；相对库存缺4架中继无人机、2组中继能源组件。

7. 注意
   严格口径下，原中继任务不可复制且资源不得跨组时，9个运输单元经实际共享中继关系连成一个整体，K=2/K=3均结构性不可行。
   因而上述5行提交值对应“按组完整复制所需中继任务”的扩展配置口径，论文中必须明确这一假设。
